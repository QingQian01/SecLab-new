# 教师端画像功能近几天工作总结

日期：2026-07-10

## 一、整体目标

近几天主要围绕 SecLab 教师端画像功能做了一轮集中修复和增强，目标是让教师能够稳定查看班级画像、学生个人画像，并在画像基础上获得面向教师的教学干预建议。

本轮工作的核心原则是：

- 学生个人画像只分析当前学生个人情况。
- 班级画像只分析班级整体情况。
- 学生个人建议与班级教学建议分层展示，不能混用口径。
- 教师端页面不展示英文技术字段、表名、乱码班级名或学生端口吻。
- AI 生成能力由后端调用 Dify API，前端不暴露 API Key，也不嵌入 Dify 聊天气泡脚本。
- Dify 不可用时保留规则兜底，保证页面仍然可用。

## 二、教师端学生个人画像修复

### 1. 页面文案与展示修复

修复了学生个人画像详情页中可见的英文技术字段，例如：

- `student_profile_snapshot`
- `Dashboard`
- `generated_question`
- `generated_question_attempt`

学生个人详情页改为更符合教师端语境的中文文案，例如：

- 最新画像快照
- 个人画像统计
- 训练与实验得分
- AI 个人教学干预建议

### 2. 学生个人建议口径修复

原先“推荐补强”容易像学生端训练推荐，也容易显得空洞。本轮将其改成教师端口径：

- 只针对当前学生个人。
- 不出现班级整体、本班共性、全班薄弱等班级判断。
- 建议内容面向教师，例如安排个人复盘、检查排查路径、抽查 AI 交互记录等。

个人画像建议的数据来源限定为：

- 当前学生五维画像得分。
- 当前学生最近训练作答。
- 当前学生活跃统计。
- 当前学生个人错误、求助或 AI 使用信号。

## 三、学生个人 AI 教学干预建议

### 1. 新增后端 AI 分析接口

新增教师端学生个人画像 AI 分析接口：

```http
POST /api/teacher/students/{user_id}/profile/ai-analysis
```

前端只调用该后端接口，不直接调用 Dify。

### 2. Dify API 后端接入

后端从环境变量读取：

```env
DIFY_API_URL
DIFY_API_KEY
```

后端请求 Dify：

```text
{DIFY_API_URL}/chat-messages
```

请求方式优先使用：

```json
{
  "inputs": {},
  "query": "学生个人画像分析 Prompt",
  "response_mode": "blocking",
  "conversation_id": "",
  "user": "teacher-student-profile-{user_id}"
}
```

### 3. 兼容 Dify Agent App streaming

实际验收时发现当前 Dify 应用返回：

```text
Agent Chat App does not support blocking mode
```

因此后端做了兼容：

- 先按规范请求 `blocking`。
- 如果 Dify 明确返回不支持 `blocking`，后端自动降级为 `streaming`。
- 后端拼接 streaming 中的 `answer` 片段。
- 再进入 JSON 解析和字段校验。

### 4. AI 返回校验与兜底

学生个人 AI 返回必须包含：

- `overallComment`
- `focusAreas`
- `dimension`
- `label`
- `score`
- `evidence`
- `teacherAction`
- `priority`

后端会拦截：

- 非 JSON 返回。
- 空返回。
- 字段缺失。
- 无效维度。
- 学生端口吻，例如“你应该”“开始训练”“推荐你”。
- 空泛建议，例如“建议加强训练”“建议重点关注”“建议补强”。

如果 Dify 超时、余额不足、返回异常或校验失败，后端返回规则兜底：

```json
{
  "scope": "student",
  "generatedBy": "rule_fallback",
  "fallbackUsed": true
}
```

前端显示固定提示：

```text
AI 分析暂不可用，已展示系统规则建议。
```

## 四、教师端班级画像修复

### 1. 班级列表展示修复

班级管理页展示以下班级层信息：

- 班级名
- 学生数
- 活跃人数
- 画像均分
- 训练均分
- 最近活跃时间

同时修复班级名显示问题：

- `????` 显示为 `未命名班级 {classId}`。
- 部分英文种子班级名映射为中文班级名。
- 空班级名不直接展示空白。

### 2. 班级与个人分层

班级页保留班级共性分析，包括：

- 班级薄弱维度。
- 低于阈值人数。
- 班级教学安排建议。

学生个人详情页只展示个人画像与个人干预建议，不混入班级平均分、班级共性薄弱点或班级教学调整建议。

## 五、班级 AI 教学安排建议

### 1. 新增班级 AI 分析接口

新增后端接口：

```http
POST /api/teacher/classes/{class_id}/ai-analysis
```

班级页调用该接口生成 AI 班级教学安排建议。

### 2. 班级 AI 输入

班级 AI 输入只包含当前班级聚合数据：

- 班级 ID 与班级名。
- 学生总数。
- 活跃学生数。
- 班级画像均分。
- 班级训练均分。
- 五维画像均分。
- 每个维度低于 70 分的人数。
- 训练作答聚合。

明确不包含：

- 单个学生个人干预建议。
- 其他班级数据。
- 其他学生跨班数据。

### 3. 班级 AI 输出结构

班级 AI 建议要求输出：

- 薄弱维度。
- 影响人数。
- 证据依据。
- 课上教学动作。
- 课后跟进动作。
- 优先级。

前端展示为：

- `课上：...`
- `课后：...`

这样比原先单句模板更适合教师实际安排教学。

### 4. 班级兜底建议

Dify 不可用或返回无效时，班级接口返回：

```json
{
  "scope": "class",
  "generatedBy": "rule_fallback",
  "fallbackUsed": true
}
```

页面显示：

```text
AI 班级分析暂不可用，已展示系统规则建议。
```

## 六、教师首页与生成题页面中文化

教师首页做了教师端聚合概览文案清理：

- 班级数
- 学生数
- 活跃学生
- 平均画像分
- 平均训练分
- AI 生成题
- 训练作答
- 班级薄弱维度
- 近期学习事件

生成题记录页也清理了可见技术字段，避免教师端看到数据库表名或内部事件名。

## 七、后端权限与数据边界

教师端接口沿用现有教师鉴权：

- 教师只能访问自己权限范围内的班级与学生。
- 管理员上下文可以访问全量。
- 学生个人 AI 分析在读取画像前会校验学生是否在教师权限范围内。
- 班级 AI 分析在读取班级学生列表前会校验班级是否在教师权限范围内。

## 十一、总结

近几天的工作已经把教师端画像功能从“能展示数据”推进到“按教师教学场景分层解释数据”：

- 教师首页看整体概览。
- 班级页看班级共性与班级教学安排。
- 学生页看个人画像与个人干预建议。
- AI 分析统一由后端调用 Dify。
- Dify 不可用时系统仍能返回可用建议。
- 教师端可见文案基本完成中文化和口径修复。

后续最值得继续做的是：在 Dify 可用后做真实页面验收，观察 AI 建议质量，并继续微调 Prompt 与展示细节。
