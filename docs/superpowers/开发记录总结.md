# SecLab 教师端与学习画像开发记录总结

> 本文汇总 2026-07-13 至 2026-07-25 的 10 组设计与实施计划（原 `plans/`、`specs/` 目录已合并删除）。
> 涉及仓库：`SecLab-FrontEnd-2`、`seclab-backend/user-service`、`experiment-module-service`、`ai-agent-service`、`database/sql`、`shujuku`。

## 总览

本阶段把教师端从“测试班 + 抽象画像分 + 固定 AI 套话”改造为真实教学闭环：教师自主建班、Excel 导入学生、课程复用、读取学生真实训练记录、手动触发 AI 分析；随后补齐能力证据、知识点风险、教学干预下发、学生能力成长与解题记录。全部能力基于真实学习事件，禁止用 mock、seed、showcase 数据生成结论。

## 一、生成题控件修复（07-13）

- 只改 `src/pages/Admin/GeneratedQuestions/index.vue`，修复审核状态徽标与“查看”按钮在窄列下换行变形。
- 审核状态改为单行语义色胶囊：待审核（琥珀）、已通过（绿）、未通过（红）、需修改（橙）。
- 查看按钮改为白底蓝描边，展开后切换为“收起”并保留 `aria-expanded`。
- 不涉及接口、数据库和事件；保留原有行展开逻辑与请求竞态保护。

## 二、教师教学班真实化（07-14）

- 教师自主创建按学年/学期使用的教学班，无管理员流程；一个教学班可按顺序关联多门可跨学期复用的课程。
- Excel 导入学生，列为“学号｜姓名｜行政班”；不存在的账号自动创建（初始密码 `123456`），已存在账号只入班、不覆盖资料，重复导入幂等。
- 教学班负责人可修改名单、课程安排、基本信息和归档状态；课程库全体教师可读可用，仅创建者可编辑删除。
- 教师端导航拆为：教学工作台、教学班、课程资源、个性化训练记录；工作台不再以“画像均分/高分排行”为核心。
- AI 班级分析只在教师点击后执行，只保留最新一次成功结果，失败时保留旧结果并给明确错误，不拼接规则套话。
- 新增接口：教学班 CRUD 与归档、学生导入预检/确认/列表/移除、教学班课程查询与更新、生成题记录查询与典型题标记、班级 AI 分析查询与触发。

## 三、教师数据范围与教学分析（07-15）

- 数据边界收紧为“当前教师自己的教学班”，教学班列表、学生、生成题、分析均按负责人过滤；课程库仍跨教师共享。
- 越权返回 `403`，资源不存在 `404`，数据不足 `422`，分析进行中 `409`，模型不可用 `503`，均在响应中给出可识别文案且不泄露内部信息。
- 教师端新增独立“教学分析”页，含“班级分析”和“学生分析”两个页签，均手动触发、只保留最新结果、无结果时显示明确空状态。
- 新增学生最新分析持久化，约束为“每位教师、每名学生一条最新结果”；不新增事件类型、不定时分析。

## 四、进展同步到团队仓库（07-16）

- 将本机已验证的教师端、教学班、教学分析、课程库、生成题与导入模板等成果按功能切片合并进团队仓库，保留目标仓库 `seclab-backend` 目录结构与清理规则。
- 明确排除：依赖、构建产物、日志、`.env`、上传文件、缓存、一次性修复脚本、汇报材料。
- 后端旧路径 `seclab/seclab` 统一映射为 `seclab-backend`，代码与文档引用同步修正。
- 验证口径：`npm run vue-tsc` / `npm run build`、相关 Gradle 与 Python 测试、SQL 结构检查、前后端字段映射核对。

## 五、教师端 130 人测试数据安全迁移（07-16）

- 采用“同库安全 Upsert”，不执行全量重置脚本，不删除现有账号和历史记录。
- 数据边界：学生学号段 `202321040501`–`202321040630`；行为与分析数据前缀 `teacher-demo-20260716-`。
- 保留已有 32 名学生的 `user_id`；清理与重建仅限带前缀数据；重复执行不增加受管行数。
- 迁移前必须完成 `userservice`、`seclab_profile` 备份，任一备份失败即停止；DDL 与数据导入分阶段，数据阶段使用事务。
- 验收：130 个唯一学生、教师角色正确、教学班恰好关联 130 名学生和 8 门课程、孤立记录为 0。

## 六、教学分析证据闭环（07-17）

- 在 `ai-agent-service` 内增量扩展，不新增微服务；读取型指标从事件表实时聚合，干预结果用独立表持久化。
- 证据链：`learning_event`、`container_command_event`、`error_event`、`challenge_completion_event`、`generated_question_attempt` → `student_profile_snapshot` 五维画像 → 教师分析结果。
- 能力证据展示分数、计算说明与可追溯条目（时间、实验上下文、结果、脱敏命令、错误类别、提示次数、是否恢复）；敏感值统一脱敏。
- 学习回放把多类事件合成时间线，优先按 `lab_session_id` 关联，缺失时用学生、模块、任务和时间窗口兜底。
- 教学干预类型：`FOCUS_GROUP`（重点辅导）、`TARGETED_PRACTICE`（专项训练）、`LESSON_EXAMPLE`（课堂案例）；创建时冻结基线，到期后可计算前后变化。
- 新增接口：班级画像重建、学生能力证据、学习回放、风险地图、干预增删改查与刷新、学生教师任务查询与开始。

## 七、知识点风险饼图与 AI 个性化教学闭环（07-18）

- 教师端“知识点 × 学生”热力矩阵改为当前实验的知识点风险饼图，只统计当前教学班、当前实验。
- 同时展示两个指标：扇形错误占比（该知识点错误次数 ÷ 本实验全部错误次数）与知识点错题率（错误次数 ÷ 有效作答次数），后者决定颜色。
- 风险分级：红 ≥60%、橙 40%–59%、黄 20%–39%、绿 <20%；同色知识点仍保持独立扇形，不合并；零错误知识点单列“掌握良好”，全对时显示绿色完成态。
- 点击扇形进入知识点详情：统计、典型错误与标准答案对照、出错学生名单、代表题与重做轨迹、AI 分析入口。
- AI 只接收该知识点的真实证据，输出结论、错误类型、教学建议与三道例题草稿（基础/巩固/迁移），状态为 `IDLE/RUNNING/READY/FAILED`，失败不覆盖上次成功结果，也不编造兜底结论。
- 例题逐题审核（待审核/已通过/需修改/未通过），可单独重生成；未通过不得下发，下发后保存不可变快照。
- 复用现有教学干预与训练链路完成“教师下发 → 学生个人中心完成 → 结果回流”，用真实作答计算完成率、正确率和干预前后错题率变化。
- 术语统一为“实验”：分析实验、本实验、班级实验分析、学生实验分析；后端 `courseId` 等字段保持不变。

## 八、具体能力成长证据（07-25）

- 用现有生产事件表中的具体事实替换泛化的“能力提升”文案，证据项返回实验会话、课程/模块/任务、URL、容器名、事件数、时长、AI 对话与消息等真实字段。
- 缺失的历史字段显示“未记录”，不补造；证据列表展示一行具体摘要（如实验名 + 状态、URL + 时长 + 事件数），可展开查看来源记录 ID。
- 目标 URL 只展示不自动打开；仅返回当前学生本人或教师自有教学班已授权范围内的证据。

## 九、学生能力成长证据（07-25）

- 在五维画像上增加“相比起点提升了多少、由哪些行为支撑、证据来自哪里、样本量与可信度如何”。
- 真实性硬约束：前端不得引用 `profileFallback.ts`、静态 JSON 或硬编码分数；后端排除 `showcase-seed`、`static-fallback` 及含 mock/demo/test/seed 的来源；无真实记录时返回空状态。
- 画像基线取教学班内第一条有效快照，当前值取最新一条；仅一条时只显示当前分数并提示“尚未形成成长对比”。
- 行为比较使用时间排序后的前 3 个与后 3 个可比任务，窗口不重叠；样本不足不计算变化率；时间指标排除容器启动、网络等待和连续 120 秒空闲，使用中位数。
- 可信度分四级：证据不足 / 出现初步迹象 / 趋势较稳定 / 证据充分；仅描述样本充分程度，不表述为因果结论。
- 首期不新增表，复用画像快照、每日特征、题目作答、学习事件、命令、错误、完成事件等；接口为学生本人和教师自有教学班两个成长查询。

## 十、学生解题记录与训练准备体验（07-25）

- 解题记录统一返回真实字段：来源类型、题目 ID、题干、题型、模块、时间、结果、得分、耗时、学生答案、标准答案、选项、解析、`contentAvailable`。
- 数据来源：课程题取 `question_submission`（题干/选项来自 `question_snapshot_json`），专项训练取 `generated_question_attempt JOIN generated_question`，Flag 记录显式标记为 `flag`。
- 历史记录无题目快照时返回真实题号并置 `contentAvailable=false`，前端提示“该历史记录未保存题干”，不补造题目。
- 推荐训练保持 7 题目标，后端并发生成；大模型主链 12 秒等待边界，超时优先复用已持久化的知识题与平台标准题（`persisted_knowledge`），不足 4 道才返回 `QUESTION_SET_GENERATION_TIMEOUT`（504）且不保存半成品。
- 前端请求 50 秒超时、显示等待秒数与 45 秒上限提示，失败后恢复可重试按钮。
- 解题记录页增加全部/错题/正确筛选、详情展开、错题高亮，默认按时间倒序。

## 关键决策与注意事项

1. 权限一律以登录令牌中的身份为准，不接受前端传入的教师 ID；前端隐藏按钮不能代替后端鉴权。
2. 教师可读范围与可写范围分离：早期为“全员可读、负责人可写”，07-15 起收紧为“仅本人教学班可读”，两者以最新设计为准。
3. 学生端与教师端共用同一份生成题与作答数据，不建复制表、不做推送任务。
4. AI 只做辅助：手动触发、只留最新成功结果、失败保留旧结果、禁止规则套话和编造数据。
5. 所有画像与成长结论必须能回溯到真实记录 ID，并携带样本量与可信度；演示/种子数据不得进入接口结果。
6. 训练题生成必须有明确耗时边界与失败码，不能用无限等待或半成品会话兜底。
7. 结构变更必须同步 `database/sql/` 与 `shujuku/`，并且字段能与 Kotlin 实体、DTO、Python 查询、前端类型逐项映射。
8. 前端拆分为纯函数与独立组件（饼图、详情抽屉、证据卡、成长卡等），便于测试与复用。

- 07-13 修改的是 `pages/Admin/GeneratedQuestions`，07-14 之后教师端生成题入口为 `pages/Teacher/GeneratedQuestions`，需确认是否仍需保留 Admin 页面引用。
- 07-18 设计只约定“知识点分析/例题/下发快照”逻辑实体，实际落库名为 `teacher_knowledge_analysis`、`teacher_knowledge_exercise`、`teacher_intervention_exercise_snapshot`，后续文档已按实际表名统一。
- 典型题标记与早期“审核状态”并存于生成题页面，审核语义已弱化，需确认是否彻底移除审核筛选。
- 班级成长排行、跨课程长期能力认证、定时 AI 分析、管理员端、正式教务排课均为明确的非目标，尚未实现。
- 130 人测试数据依赖固定学号段与前缀，迁移脚本只能在受控测试库执行，禁止用于正式数据。
