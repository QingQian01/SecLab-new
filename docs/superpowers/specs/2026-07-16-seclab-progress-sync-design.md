# SecLab 进展同步设计

## 目标

将 `D:\SecLab` 中尚未进入 `D:\Seclab-team\SecLab-Team` 的有效开发进展同步到目标 Git 仓库，同时保留目标仓库已经完成的目录重构、冗余清理和忽略规则。

本次同步以可运行的功能闭环为单位，包含功能源码、配套测试、必要 SQL 和设计/实施文档；不复制依赖、构建结果、运行日志、缓存、临时输出和一次性修复文件。

## 当前状态与差异结论

目标仓库当前位于 `main`，工作区干净，最新提交为 `959028f`。该提交将后端从 `seclab-backend` 重构到 `seclab-backend`，并清理了部分重复内容。

源项目 `D:\SecLab` 没有 Git 元数据，无法通过 cherry-pick 同步，只能按目录映射和内容差异合并。排除生成物并统一文本换行后，主要差异为：

- 前端：21 个源端新增文件、5 个实质变更文件；新增内容主要是完整教师端工作区、教学班、教学分析、课程库、生成题记录、导入模板和回归脚本。
- 后端：29 个源端新增文件、26 个实质变更文件；有效内容主要是教学班领域模型与服务、课程权限、教师分析仓储、AI 分析接口和测试。
- 数据库：1 个新增结构测试和 4 个初始化脚本变更；`shujuku` 中的差异仅为换行格式，不需要覆盖。
- 文档：源项目包含教师端教学班、教学分析和生成题控件的设计与实施计划；目标仓库重构时删除了这些文档。

## 同步策略

采用“按功能差异合并”，不做目录镜像覆盖。

冲突处理顺序如下：

1. 目标仓库的目录结构和 `.gitignore` 规则优先。
2. 同一路径存在实质内容差异时，源项目中已验证的功能实现优先，但必须检查其对目标路径和配置的引用。
3. 目标仓库独有文件默认保留，除非它只是乱码命名静态资源的旧副本。
4. 源项目中曾被目标仓库明确清理的临时部署脚本、测试网页和输出产物不恢复。
5. 所有后端源路径从 `D:\SecLab\seclab\seclab` 映射到目标 `seclab-backend`，代码和文档中的有效路径说明同步改为新目录名。

## 数据流与错误处理

教师登录后由前端路由进入教师工作区。前端通过目标仓库已有 API 封装调用用户服务、课程服务和 AI 服务。用户服务负责身份、教学班、成员和课程安排；课程服务负责公共课程及创建者权限；AI 服务读取当前教师权限范围内的数据并生成班级或学生分析。

所有权限判断在后端执行，前端隐藏按钮不能替代鉴权。资源不存在返回 `404`，越权返回 `403`，重复分析返回 `409`，数据不足返回 `422`，模型服务不可用返回 `503`。导入预检失败返回逐行错误，确认操作保持幂等。

## 验证方案

同步完成后执行以下验证：

1. `git diff --check`，确认没有冲突标记、尾随空格或异常补丁。
2. 在 `SecLab-FrontEnd-2` 运行 `npm run vue-tsc` 和 `npm run build`。
3. 在 `seclab-backend` 运行用户服务和课程服务的相关 Gradle 测试与构建。
4. 在 `seclab-backend/ai-agent-service` 运行教师仓储、AI 分析和 API 错误相关 Python 单元测试，并执行 `py_compile`。
5. 运行 `database/sql/test_teacher_teaching_class_schema.py`，检查必要表、字段、索引及唯一约束。
6. 检查前端 API 字段、Kotlin DTO/实体、Python 查询和 SQL 字段映射。
7. 检查 Git 状态，确认没有依赖、构建产物、环境文件、日志或临时脚本进入提交。

若本地缺少数据库、Docker、Dify 或其他外部服务，只运行不依赖外部服务的最小验证，并在交付说明中明确未验证项和剩余风险。

## 验收标准

1. 教师能够进入独立教师端导航并使用教学概览、教学班、教学分析、生成题记录和课程库。
2. 教师能够创建教学班、预检并确认学生导入、安排多门课程，且重复导入不会产生重复成员。
3. 教师只能访问自己教学班中的学生、生成题和分析；公共课程可跨教师复用，只有创建者可修改课程。
4. 班级分析与学生分析分别使用真实数据，AI 调用失败时错误与兜底行为明确。
5. 必要数据库结构、接口、测试和设计文档均已进入目标仓库。
6. 目标仓库保持 `seclab-backend` 目录结构，不恢复已清理的冗余目录和生成物。
7. 前端检查、相关后端测试、Python 测试和 SQL 结构测试通过，或对无法执行的外部依赖验证给出明确说明。
