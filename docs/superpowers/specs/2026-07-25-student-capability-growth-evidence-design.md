# 学生能力成长证据设计

## 目标

在现有五维学习画像基础上，让学生和教师不仅看到“当前能力分数”，还能够直观看到：

- 相比学习起点提升了多少；
- 哪些可观察行为支撑这个变化；
- 证据来自哪些题目、实验与学习事件；
- 当前结论有多少样本、可信度如何；
- 数据不足时为什么暂时不能得出稳定结论。

首期同时覆盖学生个人画像页和教师端单个学生分析页。班级成长排行、复杂自适应测量和跨课程长期能力认证不在首期范围内。

## 真实性硬约束

成长功能只能使用生产学习链路真实写入数据库的数据，并通过后端接口读取。以下规则属于不可降级的验收条件：

- 前端不得导入或调用 `src/mock/profileFallback.ts`、静态 JSON、硬编码分数、随机数或浏览器本地估算；
- 后端不得使用 showcase、seed、mock、demo、test 或 static-fallback 数据生成成长分数和行为结论；
- 已知来源值 `showcase-seed`、`static-fallback` 以及包含 `mock`、`demo`、`test`、`seed` 的测试来源必须排除；
- 没有真实记录时返回空状态或“证据不足”，不得为了页面完整而补造数据；
- 每个行为指标必须携带真实记录数量、来源类型和可追溯记录标识；
- 能力快照必须能证明由合格生产事件构建；无法确认来源的旧快照不得用于成长对比；
- 页面文案不得把相关性描述成因果关系，不得把 AI 生成的评价当作行为事实；
- 开发和自动化测试可以使用测试夹具，但测试数据不得进入生产接口结果或学生页面。

现有 `src/mock/profileFallback.ts` 可以继续服务明确标记的演示页面，但成长组件和成长接口不得引用它。

## 设计选择

采用“画像快照变化 + 可比行为证据”方案。

能力分数变化复用 `student_profile_snapshot` 的历史快照；行为变化从已有题目作答、实验命令、错误、求助、重试与完成事件中聚合。不同实验不直接比较实验总耗时，而是比较被标记为相同能力类型、知识点、题型和难度的行为。

没有采用以下方案：

- 请求时重算全部画像：结果容易随查询时间波动，响应成本也更高。
- 新建成长事实表：首期数据规模不需要额外同步链路，后续出现班级大规模统计性能问题时再引入。
- 强制学生重复同一实验：会产生记忆效应，不能真实体现能力迁移。

## 能力成长口径

### 画像基线与当前值

每次请求按教学班范围读取学生画像快照：

1. 基线为该学生在教学班内第一条有效快照；
2. 当前值为同一教学班内最新一条有效快照；
3. 每个维度的变化量为 `current_score - baseline_score`；
4. 只有一条快照时展示当前分数，并标记“尚未形成成长对比”；
5. 快照缺失时不返回伪造分数，页面进入空状态并提示先完成学习任务或重建画像。
6. 快照只有在 `profile_summary_json.data_provenance.mode` 为 `production_events` 且存在合格原始记录时才可参与成长比较；
7. 不满足来源要求的旧快照标记为不可比较，不能与新快照混算。

首期维度保持现有命名：

- `knowledge_mastery`：知识掌握；
- `troubleshooting`：故障排查；
- `autonomy`：自主学习；
- `ai_collaboration`：AI 协同；
- `engagement`：学习投入；
- `overall`：综合能力。

### 行为比较窗口

行为证据使用“早期窗口”和“近期窗口”比较：

- 早期窗口：按时间排序后的前 3 个可比任务；
- 近期窗口：按时间排序后的后 3 个可比任务；
- 早期与近期窗口不得使用同一个任务；
- 同一指标少于 2 个早期样本或 2 个近期样本时，不计算百分比变化；
- 题目按知识点、题型和难度分桶；
- 实验行为按能力标签和阶段类型分桶，例如定位、构造、排错、恢复、验证；
- 无法确定可比关系的数据只作为事件证据展示，不参与趋势结论。
- 任何被识别为演示、种子、mock 或测试来源的数据既不进入窗口，也不计入样本量。

### 时间指标

时间只统计有效活动时间：

- 排除容器启动和平台网络等待；
- 连续 120 秒没有操作的区间记为空闲，不计入有效时间；
- 不比较不同难度、不同类型任务的绝对总耗时；
- 时间缩短但正确率、完成率或成功率下降时，不标记为正向提升；
- 首期使用中位数，避免单次离开页面造成的极端值污染。

### 行为指标

#### 知识掌握

- 可比题目正确率；
- 首次作答正确率；
- 同知识点错误数量；
- 间隔后再次遇到同知识点时的正确表现。

#### 故障排查

- 从错误发生到首次成功恢复的有效时间；
- 每个成功任务前的无效命令数量；
- 遇错后最终成功恢复率；
- 首次方案成功率。

#### 自主学习

- 无直接提示完成的任务比例；
- 每个任务的提示请求次数；
- 查看解析前的有效尝试次数；
- 首次独立完成的新类型任务数量。

#### AI 协同

- AI 建议后是否进行了验证；
- AI 建议被采用后是否最终完成任务；
- 能否提供错误、上下文和已尝试方案等有效提问信息；
- 不使用 AI 消息数量作为正向能力指标。

#### 学习投入

- 有效操作时长；
- 已开始任务的完成率；
- 按计划完成的学习任务数量；
- 连续有效学习情况，不把页面停留或挂机计入。

## 可信度

每个成长指标返回样本数和可信度：

- `insufficient`：任一比较窗口少于 2 个样本；
- `emerging`：早期和近期各有 2 个样本；
- `moderate`：早期和近期各有至少 3 个样本；
- `high`：各有至少 5 个样本，并且变化方向在多个任务中一致。

页面对应文案：

- `insufficient`：证据不足；
- `emerging`：出现初步迹象；
- `moderate`：趋势较稳定；
- `high`：证据充分。

可信度描述的是样本充分程度，不代表统计学因果结论。

## 数据结构

首期不新增数据库表。

复用：

- `student_profile_snapshot`：历史五维画像；
- `student_profile_feature_daily`：每日聚合特征；
- `generated_question_attempt`：题目作答、正确性、分数和耗时；
- `learning_event`：通用学习事件；
- `container_command_event`：实验命令；
- `error_event`：错误与严重程度；
- `challenge_completion_event`：Flag 或实验完成；
- 已有求助、AI 对话和实验会话关联数据。

若现有任务缺少能力标签、阶段类型或可靠难度，首期只使用可以明确映射的题目和事件，不能通过标题猜测后写入稳定结论。

真实字段映射如下：

| 指标 | 真实数据表与字段 |
|---|---|
| 题目正确率 | `question_submission.is_correct` 或 `generated_question_attempt.is_correct` |
| 题目有效作答时间 | `question_submission.cost_time` 或 `generated_question_attempt.cost_time` |
| 可比题目 | `knowledge_point_id`、`question_type`，以及 `generated_question.difficulty` |
| 实验完成与总耗时 | `challenge_completion_event.completion_status`、`total_time_seconds` |
| AI 求助次数 | `challenge_completion_event.total_ai_ask_count`、`ai_message.hint_level` |
| 命令成败与耗时 | `container_command_event.exit_code`、`duration_ms`、`executed_at` |
| 错误与恢复 | `error_event.command_id`、`error_category`、`occurred_at`，关联后续成功命令或完成事件 |
| 实验有效活动区间 | `lab_session.start_time/end_time` 与会话内事件时间戳 |
| 五维能力快照 | `student_profile_snapshot` 的五维分数、`computed_at`、来源区间与来源说明 |

指标查询必须保留数据血缘。对没有 `source` 字段的记录，通过训练会话、实验会话、提交记录或画像来源说明验证其父级来源；无法验证时不纳入成长结论。

## 后端结构

在现有 `ai-agent-service` 内增量扩展，不新增微服务。

新增独立成长读取模块，职责包括：

1. 校验学生本人或教师对教学班和学生的访问权限；
2. 读取教学班范围内的历史画像快照；
3. 选取基线、当前值并计算维度变化；
4. 聚合可比行为窗口；
5. 生成结构化证据、样本量和可信度；
6. 对命令、错误和 AI 内容执行现有截断与脱敏规则。
7. 过滤非生产来源，并返回被排除记录数量和原因；
8. 返回计算版本和数据血缘，保证同一版本下结果可复算。

成长聚合使用纯函数拆分，数据库读取与指标计算分离，便于单元测试覆盖时间排除、窗口选取、样本不足和反向指标等规则。

## API

### 学生端

`GET /api/students/{student_id}/capability-growth`

查询参数：

- `teachingClassId`：可选；未传时使用学生当前有效教学班。

权限：

- 登录学生只能读取本人；
- 教师不能通过此接口绕过教学班所有权校验。

### 教师端

`GET /api/teacher/teaching-classes/{class_id}/students/{student_id}/capability-growth`

权限：

- 当前用户必须是该教学班教师；
- 学生必须属于该教学班。

## 学生端页面

在现有个人画像页增加“我的能力成长”区，放在当前统计概览之后、专项训练之前。

页面结构：

1. 综合成长卡：显示当前综合能力、相对基线变化和对比周期；
2. 五维变化卡：显示 `起点 → 当前`、变化值和可信度；
3. 成长趋势：使用现有 Chart.js 绘制最多 8 个画像快照，不新增图表依赖；
4. 维度详情：点击维度后展示行为指标；
5. “为什么提升”：展示 3 至 5 条近期证据；
6. 数据说明：展示样本量、可比口径和可信度解释。
7. 数据来源：显示“来自真实实验与作答记录”、统计截止时间和计算版本；不显示不存在的记录。

正向文案示例：

> 近期 3 个可比排错任务中，遇错后恢复时间中位数由 11 分钟降至 7 分钟，同时任务完成率没有下降。

非正向或数据不足文案示例：

> 目前只有 1 个可比任务，暂不判断时间变化。继续完成同类实验后生成稳定趋势。

颜色不作为唯一信息载体。所有上升、下降、证据不足状态同时使用文字和符号表达。

## 教师端页面

在教师教学分析的单个学生视图中增加“能力成长”区，复用学生端的展示口径，但提供更多审计信息：

- 基线和当前快照时间；
- 每项指标的早期、近期样本量；
- 可比任务范围；
- 证据来源和发生时间；
- 数据不足或不纳入比较的原因。

教师端继续保留现有“能力分数与证据”和“学习回放”。成长区回答“发生了什么变化”，现有证据区回答“当前分数由什么构成”，学习回放回答“具体过程是什么”，三者不重复替代。

## 状态与错误处理

- 加载中：使用与现有页面一致的骨架或加载提示；
- 无快照：提示完成学习任务后生成画像；
- 单快照：展示当前能力，隐藏伪造变化值；
- 行为样本不足：显示样本量和“证据不足”；
- 部分事件表不可用：仍返回可用的画像变化，并在 `message` 中说明行为证据不完整；
- 只有演示、种子或 mock 数据：视为没有合格真实数据，不能降级展示这些记录；
- 请求失败：保留页面上一次成功结果并显示重试入口；
- 无权限：返回 403，不向前端暴露教学班或学生是否存在的额外信息。

## 安全与隐私

- 学生只能读取本人数据；
- 教师只能读取自己教学班的成员；
- 命令中的 token、password、cookie、authorization 等敏感值沿用现有脱敏；
- 错误输出、AI 对话和命令内容继续执行长度截断；
- 页面不展示班级其他学生的个人数据；
- 首期不生成跨班级能力排名。
- 数据来源过滤在后端执行，不能依赖前端隐藏；
- 画像重建时在 `profile_summary_json.data_provenance` 写入来源模式、记录数量、计算版本和排除数量。

## 测试策略

### 后端

使用 TDD 覆盖：

- 正确选择教学班内首条和最新快照；
- 单快照和无快照状态；
- 早期、近期窗口不重叠；
- 样本不足时不计算变化率；
- 时间缩短但正确率下降时不标记提升；
- 空闲时间和平台等待不计入有效时间；
- 中位数计算不受极端值影响；
- 五维指标与证据映射；
- 学生本人鉴权、教师教学班所有权与成员校验；
- 敏感命令脱敏。
- showcase、seed、mock、demo、test 和 static-fallback 来源被排除；
- 旧快照缺少生产来源证明时不进入成长对比；
- 响应中的来源记录 ID 能对应到测试数据库中的真实记录；
- 客户端传入伪造分数或变化量不会影响接口结果。

### 前端

使用 Vitest 覆盖纯展示逻辑和组件状态：

- 正负变化值格式化；
- 时间、比例和次数单位格式化；
- 四种可信度文案；
- 单快照、证据不足和部分数据错误状态；
- 点击维度切换指标与证据；
- 学生端和教师端使用相同口径。
- 成长组件不导入或调用 `profileFallback.ts`；
- 空数据和接口错误时不出现任何静态演示分数。

运行 `npm run vue-tsc` 和 `npm run build` 验证类型与生产构建。

### 真实接口联调

- 使用实际登录学生完成题目和实验操作；
- 查询数据库确认对应作答、命令、错误、完成和画像快照记录；
- 调用学生成长接口，核对响应中的记录 ID、样本数和计算结果；
- 使用实际教师账号调用教师成长接口，确认同一学生得到相同口径；
- 在数据库仅有演示数据时确认接口返回证据不足；
- 检查浏览器网络响应和页面 DOM，确认没有 `mock-`、`static-fallback`、`showcase-seed` 或硬编码示例值。

## 验收标准

- 学生能够在个人画像页看到综合能力及五维能力的基线、当前值和变化量；
- 任一能力维度可展开查看至少一种行为指标或明确的数据不足原因；
- 时间指标只在可比任务和正确率未下降时显示正向提升；
- 不要求学生重复同一实验；
- 学生能够看到证据来源、样本量和可信度；
- 教师端同一学生显示与学生端一致的能力变化；
- 教师可以查看更详细的比较窗口和证据来源；
- 单快照、无快照、部分数据不可用和无权限均有明确处理；
- 新接口通过权限、脱敏和聚合规则测试；
- 所有成长分数和行为指标来自真实数据库接口，能够追溯到原始记录；
- 演示、种子、mock、test 和 static-fallback 数据不会进入结果；
- 没有合格真实数据时页面如实显示空状态；
- 使用真实学生行为完成一次数据库、接口、页面三方核对；
- 前端单元测试、类型检查和生产构建通过。
