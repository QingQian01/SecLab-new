# 学生解题记录与训练准备体验设计

## 目标

让学生能够用真实学习数据回答“我做过哪些题、哪里做错、为什么错”，并让推荐训练题生成从无限等待变为有明确耗时边界、可失败、可重试的过程。

## 已确认的问题

1. 画像页推荐训练固定请求 7 题。后端逐题串行生成，最多检查 8 个题位，每题最多调用大模型 2 次；底层单次 HTTP 超时为 90 秒，因此页面可能长时间停留在“正在准备训练题”。
2. `profile_dashboard_repository._question_records` 只读取提交编号、题号和模块号，尽管真实 `question_submission.question_snapshot_json` 已保存题干和选项，接口仍返回“问题 #1”。
3. 画像页只汇总 `question_submission` 与 Flag，未读取 `generated_question_attempt`，专项训练中的错误作答因此不会进入解题记录。
4. 当前前端只渲染静态表格，没有详情入口，也没有错题筛选。

## 方案

### 训练准备

- 推荐训练保持 7 题目标，但后端将各题生成任务并发执行，避免 7 次串行等待。
- 整组生成设置 45 秒硬超时。超时后返回 `QUESTION_SET_GENERATION_TIMEOUT` 和 HTTP 504，不保存半成品训练会话。
- 每个题位仍保留最多 2 次质量重试；达到至少 4 道合格题时可以返回真实的部分题组，少于 4 道则失败。
- 前端请求设置 50 秒超时，显示已等待秒数以及“通常 10–30 秒，超过 45 秒可重试”的真实提示。失败后恢复按钮，不再无限转圈。

### 解题记录

统一返回以下真实字段：

- `id`、`sourceType`、`questionId`、`title`、`stem`、`questionType`
- `module`、`time`、`result`、`isCorrect`、`score`、`costTime`
- `studentAnswer`、`standardAnswer`、`options`、`explanation`
- `contentAvailable`

数据来源：

- 课程题：`question_submission`，题干、选项来自 `question_snapshot_json`，学生答案和标准答案来自对应 JSON 字段。
- 专项训练题：`generated_question_attempt JOIN generated_question`，题干、参考答案、解析均来自已落库生成题。
- Flag 记录继续保留，但明确标记为 `flag`，不伪装成普通选择题。

若历史记录没有保存题目快照，接口返回真实题号并设置 `contentAvailable=false`；前端显示“该历史记录未保存题干”，不补造题目。

### 前端交互

- 解题记录顶部显示全部、错题、正确三个筛选按钮和真实数量。
- 每条记录显示题目标题或题干摘要、来源、题型、结果、分数、耗时。
- 点击“查看详情”展开题干、选项、我的答案、正确答案和解析。
- 错题使用醒目但不过度的红色边框与“错题”标签；默认按时间倒序，保证近期错误可见。
- 姜理想当前真实数据没有错题，因此页面应显示“错题 0”，同时两条正确记录可展开查看完整 SQL 注入题目。

## 错误处理与真实性

- 不启用 `profileFallback`，不新增种子或 mock 数据。
- 大模型不可用、超时、生成不足 4 题时均返回明确错误码。
- JSON 内容解析失败时保留原始文本，不吞掉整条记录。
- 新提交继续保存题目快照，保证未来记录可追溯；初始化 SQL 同步增加字段。

## 验收

1. 姜理想账号画像页显示两条真实 SQL 注入课程题，点击可查看题干、四个选项、本人答案和正确答案。
2. 页面明确显示错题数量为 0，不声称存在错题。
3. 有专项训练错题的真实账号能够在“错题”筛选中看到题目详情。
4. 训练题准备在 45 秒内成功或明确失败，按钮恢复为可重试状态，页面不会无限加载。
5. 后端测试、前端组件测试、类型检查与构建通过，并完成浏览器交互验收。
