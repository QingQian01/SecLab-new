# SecLab 完整运行配置设计

## 目标

让 `fix/real-learning-loop-20260722` 分支在新环境中能够明确、完整地配置前端、用户服务、实验模块服务、Docker 服务、AI Agent、Dify 与 MySQL，避免因变量漏配而在页面运行后才出现功能不可用。

## 实现范围

1. 补齐 `SecLab-FrontEnd-2/.env.example`：
   - 用户服务地址
   - 实验模块服务地址
   - 图片服务地址
   - Docker API 地址
   - AI Agent 地址
2. 补齐 `seclab-backend/ai-agent-service/.env.example`：
   - Dify API、应用与工作流配置
   - Dify 知识库模式
   - 单题生成样例校验
   - Flag 答案映射
   - Docker 工具鉴权与容器白名单
   - AI Agent 监听、CORS 和 MySQL 配置
3. 新增 AI Agent 配置检查脚本：
   - 加载指定 `.env`，默认检查当前服务目录的 `.env`
   - 只输出变量名称和检查结果，不输出变量值
   - 检查必填项是否缺失或仍为示例占位符
   - 校验端口、布尔开关和 JSON 配置格式
   - 必填项无效时返回非零退出码
4. 更新部署说明：
   - 复制两个 `.env.example`
   - 填写运行环境自己的密钥
   - 启动前执行配置检查
   - 给出 Dify 与服务健康检查地址

## 配置边界

- Git 中只保存变量名、安全默认值与占位符。
- 本机真实 `seclab-backend/ai-agent-service/.env` 继续由 `.gitignore` 排除。
- 检查脚本不得打印 Dify 密钥、数据库密码、工具密钥或 Flag。
- 不新增数据库表，不修改现有 API 路径和响应结构。

## 错误处理

- `.env` 不存在：指出复制模板的命令并失败退出。
- 必填变量缺失或为占位符：逐项列出变量名并失败退出。
- `FLAG_ANSWERS_JSON` 不是 JSON 对象：指出格式错误并失败退出。
- 端口或布尔变量格式错误：指出变量名和允许格式并失败退出。
- 可选变量为空：标记为可选，不阻塞启动。

## 验证

- 单元测试覆盖完整配置、缺少密钥、占位符、非法端口、非法布尔值和非法 JSON。
- 检查仓库模板包含代码实际读取的全部环境变量。
- 运行前端测试与生产构建。
- 运行 AI Agent 单元测试。
- 提交前执行差异检查与密钥扫描，确认真实 `.env` 未进入 Git。
