# 教师工作台页面滚动修复设计

## 问题

教师工作台的教学班页面在学生名单超过一屏时仍无法向下滚动。页面内容已经渲染到视口之外，但鼠标滚轮、触控板和浏览器滚动条都不能访问下面的内容。

根因位于布局边界：`App.vue` 的应用根节点使用固定定位和 `100%` 高度，因此页面内容不会扩展浏览器文档滚动区；教师布局的 `.teacher-main` 只有 `min-height: 100vh` 和 `overflow: auto`，没有受约束的实际高度，自身也不会形成内部滚动区。

## 选择方案

采用教师工作台局部滚动，不修改全局应用根节点。

- `.teacher-shell` 固定为视口高度并隐藏外层溢出。
- `.teacher-main` 使用视口高度，纵向自动滚动、横向隐藏溢出。
- 左侧教师导航继续固定，不随右侧长内容滚动。
- 移动端保留顶部菜单占位，右侧内容仍可纵向滚动。

不采用取消 `App.vue` 固定定位的方案，因为它会同时改变学生端、聊天页和管理端的布局行为；也不采用只滚动学生表格的方案，因为教学安排和其他教师页面同样可能产生长内容。

## 修改范围

只修改 `SecLab-FrontEnd-2/src/layout/Teacher/index.vue` 的教师布局 CSS，并新增一个静态回归测试。教学班页面结构、数据请求、表格样式和数据库均不修改。

目标 CSS 行为：

```css
.teacher-shell {
  height: 100vh;
  height: 100dvh;
  overflow: hidden;
}

.teacher-main {
  height: 100vh;
  height: 100dvh;
  min-height: 0;
  overflow-x: hidden;
  overflow-y: auto;
}
```

保留 `100vh` 作为兼容回退，支持动态视口单位的浏览器使用 `100dvh`。

## 验证

- 回归测试确认教师外壳具有受约束视口高度和隐藏外层溢出。
- 回归测试确认教师内容区具有受约束视口高度、`min-height: 0` 和纵向滚动。
- 运行 `vue-tsc` 和生产构建。
- 在当前运行的教学班页面刷新后，确认滚轮可以从第一名学生滚动到名单末尾。
- 确认左侧导航保持固定，页面没有横向滚动条。
- 在窄视口确认移动端菜单与内容滚动仍可使用。

浏览器插件和项目 Playwright 当前均不可用，因此自动化验证以静态回归、类型检查和构建为主，最终滚动交互在当前本地页面中人工确认。
