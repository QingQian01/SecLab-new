#### 3.1 在 onMounted 前添加 syncGuidanceAlertsToMessages 函数

```typescript
// ── Phase 3: Proactive Guidance 同步到消息列表 ───────────────
/**
 * 把 guidanceAlerts 同步到 messages 数组：
 * - 新 alert → push assistant message（isGuidance=true）
 * - 已存在 alert（按 signal_id 匹配）→ 更新 content/streamContent/isStreaming/guidance_status
 * 找不到匹配 alert 的 guidance 消息保留（用户可手动滚动查看历史）。
 */
function syncGuidanceAlertsToMessages() {
  for (const alert of guidanceAlerts.value) {
    const existingIdx = messages.value.findIndex(
      (m) => m.isGuidance && m.signal_id === alert.signal_id
    )
    if (existingIdx === -1) {
      // 新 alert → push 新消息
      messages.value.push({
        role: 'assistant',
        content: alert.content,
        streamContent: alert.content,
        timestamp: new Date(alert.started_at),
        isStreaming: alert.status === 'streaming',
        isGuidance: true,
        signal_id: alert.signal_id,
        trigger_reason: alert.trigger_reason,
        guidance_status: alert.status,
      })
    } else {
      // 已存在 → 原地更新
      const msg = messages.value[existingIdx]
      msg.content = alert.content
      msg.streamContent = alert.content
      msg.isStreaming = alert.status === 'streaming'
      msg.guidance_status = alert.status
    }
  }
  nextTick(() => scrollToBottom())
}
```

## 4. Phase 3.2.2 待做（FloatingChatButton.vue）

### 架构决策（重要）

**SSE 订阅应放在 FloatingChatButton.vue（始终挂载），而非 FloatingChat.vue（v-if 条件挂载）**。

原因：
- FloatingChat 用 `v-if="chatVisible"` 挂载，关闭时卸载 → SSE 断开
- 若 SSE 在 FloatingChat 中，聊天关闭时收不到 guidance 信号 → 主动提示失效
- FloatingChatButton 始终挂载（它是入口组件），适合放 SSE 订阅
- guidanceAlerts 在 useLabState 中全局共享，FloatingChat 打开后读取已累积的 alerts

### 实施计划

```typescript
// FloatingChatButton.vue <script setup>
import { ref, watch, onMounted, onUnmounted } from 'vue'
import {
  currentLabContainer,
  labStartTime,
  setLabRunning,
  currentLabContext,
  guidanceUnreadCount,
  guidanceAlerts,
  addGuidanceAlert,
  updateGuidanceAlert,
  appendGuidanceChunk,
} from '../composables/useLabState'
import { subscribeGuidanceStream, type GuidanceStreamEvent } from '../api'

// SSE 订阅 unsubscribe 函数
let unsubscribeGuidance: (() => void) | null = null

/** 根据 labSessionId 订阅 guidance SSE */
function setupGuidanceSubscription(labSessionId: string) {
  // 先取消旧订阅
  if (unsubscribeGuidance) {
    unsubscribeGuidance()
    unsubscribeGuidance = null
  }
  if (!labSessionId) return

  unsubscribeGuidance = subscribeGuidanceStream(labSessionId, {
    onReady: (evt) => {
      console.log('[guidance] SSE subscribed:', evt.lab_session_id)
    },
    onGuidanceStart: (evt) => {
      addGuidanceAlert({
        signal_id: evt.signal_id,
        trigger_reason: evt.trigger_reason,
        conversation_id: evt.conversation_id,
        error_context: evt.error_context,
        content: '',
        status: 'streaming',
        started_at: evt.ts,
      })
    },
    onChunk: (evt) => {
      appendGuidanceChunk(evt.signal_id, evt.content)
    },
    onError: (evt) => {
      updateGuidanceAlert(evt.signal_id, {
        status: 'error',
        error_message: evt.message,
        ended_at: evt.ts,
      })
    },
    onGuidanceEnd: (evt) => {
      updateGuidanceAlert(evt.signal_id, {
        status: 'done',
        message_id: evt.message_id,
        conversation_id: evt.conversation_id,
        ended_at: evt.ts,
      })
    },
    onParseError: (raw, err) => {
      console.warn('[guidance] parse error:', raw, err)
    },
  })
}

// 监听 labSessionId 变化 → 重新订阅
watch(
  () => currentLabContext.value.labSessionId,
  (newId) => {
    if (newId) setupGuidanceSubscription(newId)
  }
)

onUnmounted(() => {
  if (unsubscribeGuidance) unsubscribeGuidance()
})
```

## 5. 关键技术决策与上下文

### 5.1 FrustrationTracker 评分规则（关键）

- 每次错误 +1（基础）；同 signature 60s 内重复 ≥2 次 → **额外 +2**（即 delta=1+2=3）
- 每次非零 exit 命令 +1；5min 窗口同 normalizedCmd ≥3 次 → 额外 +1（即 delta=1+1=2）
- observeError/observeCommand 内部自动调 tryTrigger：score >= threshold 且距上次触发 > cooldown → 触发并清零
- **关键推论（threshold=3）**：同 signature 第 2 次错误 score=1+3=4 ≥ 3 → **第 2 次即触发**（非第 3 次）

### 5.2 异步后台任务模式

- `/api/guidance/signal` 立即返回 202，Dify 调用在 `asyncio.create_task` 中进行
- SSE 订阅独立端点 `/api/guidance/stream/{lab_session_id}` 不鉴权
- guidance_stream_registry：单 worker 部署约束，进程内 asyncio.Queue 广播
- **无订阅者时跳过 Dify 调用**：节省成本（guidance_service.stream_guidance_to_subscribers 开头检查）

### 5.3 verify_tool_key 复用

`/api/guidance/signal` 复用 `verify_tool_key` Security 依赖（支持 `X-SecLab-Token` 与 `Authorization: Bearer`，TOOL_API_KEY 为空时放行）。docker-service 的 `signal-token` 应与 `TOOL_API_KEY` 保持一致。

### 5.4 SSE 订阅位置决策（重要）

- **SSE 订阅放 FloatingChatButton.vue（始终挂载）**，不放 FloatingChat.vue（v-if 条件挂载）
- guidanceAlerts 全局共享，FloatingChat 打开后读取已累积的 alerts
- 这样聊天关闭时仍能接收 guidance 信号，打开后可见历史

### 5.5 ensure_guidance_schema() 自愈建表

`guidance_service.save_guidance_proactive_note()` 调用前先 `ensure_guidance_schema()`，与 `error_repository.save_error_event` 风格一致。`_schema_ready` 标志保证只建表一次。

### 5.6 _build_dify_inputs JSON 截断修复

原实现 `json.dumps(recent_commands)[:800]` 会截断成非法 JSON。修复为先取最后 5 条再序列化（`raw_commands[-5:]`），避免大量命令撑爆 800 字符上限。

### 5.7 测试约定

- ai-agent-service 用 `unittest.TestCase`（非 pytest fixtures）
- 直接 `import` 模块，用 `mock.patch.object` 替换 DB 依赖
- Windows 上 `python` 不在 PATH，用 `py` launcher 代替
- PowerShell 用 `;` 分隔命令（不支持 `&&`）

### 5.8 Kotlin daemon fallback

`-Dkotlin.compiler.execution.strategy=in-process` 可绕过 daemon 连接问题（非阻塞警告，Gradle 自动 fallback）。

## 7. 已知风险与未决事项

### 7.1 单 worker 部署约束

guidance_stream_registry 用进程内 asyncio.Queue，仅支持单 uvicorn worker。多 worker 部署需改用 Redis Pub/Sub（当前不做，部署文档需注明）。

### 7.2 SSE 在 Vite dev proxy 下的缓冲

vite.config.ts 已有 `/api/agent` → 8010 代理，但 subscribeGuidanceStream 直接用 `AGENT_BASE_URL`（不走代理），靠后端 CORSMiddleware 允许前端 origin。需确认 CORS_ORIGINS 配置包含前端 dev origin（默认 `http://localhost:5173`）。

### 7.3 FloatingChat 消息持久化

FloatingChat.vue 的 `loadMessagesFromStorage` 从 localStorage 读，但代码中**没有 saveMessagesToStorage**（只有 load）。guidance 消息混入 messages 数组后不会持久化，刷新页面后消失。这是现有行为，本次不修改。

### 7.4 Dify conversation_id 回填

`ensure_guidance_conversation` 不修改 `dify_conversation_id` 列（避免 UNIQUE 约束冲突）。首次 Dify 调用后由 `update_conversation_after_stream` 回填真实 `dify_conversation_id`。

### 7.5 docker-service GuidanceSignalClient

本进度文档覆盖 ai-agent-service 与前端。docker-service 侧的 `GuidanceSignalClient`（向 `/api/guidance/signal` 发 POST）应在 Phase 1 已完成（上一会话），但需要确认其字段与 `GuidanceSignalRequest` Pydantic 模型对齐。

def dispatch_signal_task(signal: dict[str, Any]) -> dict[str, Any]:
    prepared = handle_signal(signal)
    lab_session_id = prepared["lab_session_id"]
    signal_id = signal.get("signal_id") or f"sig-{uuid4()}"

    asyncio.create_task(

            signal_id=signal_id,
            trigger_reason=trigger_reason,
            conversation_id=prepared["conversation_id"],

            query=prepared["query"],
            inputs=prepared["inputs"],
            user_id=prepared.get("user_id"),
            error_classified=prepared.get("error_classified"),
        )
    )

    return {
        "signal_id": signal_id,
        "conversation_id": prepared["conversation_id"],
        "subscriber_count": guidance_stream_registry.subscriber_count(lab_session_id),
        "accepted": True,
    }

async def stream_guidance_events(lab_session_id: str):
    async def event_stream():
        try:

### 9.4 api.ts subscribeGuidanceStream（前端 SSE 订阅）

```typescript
export function subscribeGuidanceStream(
    labSessionId: string,
    callbacks: GuidanceStreamCallbacks
): () => void {
    const controller = new AbortController();
    const url = `${AGENT_BASE_URL}/api/guidance/stream/${encodeURIComponent(labSessionId)}`;
    (async () => {
        try {
            const response = await fetch(url, {
                method: 'GET',
                signal: controller.signal,
                headers: { 'Accept': 'text/event-stream', 'Cache-Control': 'no-cache' },
            });
            if (!response.ok || !response.body) return;
            const reader = response.body.getReader();
            const decoder = new TextDecoder('utf-8');
            let buffer = '';
            while (true) {
                const { done, value } = await reader.read();
                if (done) break;
                buffer += decoder.decode(value, { stream: true });
                const lines = buffer.split('\n');
                buffer = lines.pop() ?? '';
                for (const line of lines) {
                    const trimmed = line.trim();
                    if (!trimmed.startsWith('data:')) continue;
                    const raw = trimmed.slice(5).trim();
                    if (!raw || raw === '[DONE]') continue;
                    try {
                        const event = JSON.parse(raw) as GuidanceStreamEvent;
                        switch (event.type) {
                            case 'ready': callbacks.onReady?.(event); break;
                            case 'guidance_start': callbacks.onGuidanceStart?.(event); break;
                            case 'chunk': callbacks.onChunk?.(event); break;
                            case 'error': callbacks.onError?.(event); break;
                            case 'guidance_end': callbacks.onGuidanceEnd?.(event); break;
                        }
                    } catch (err) {
                        callbacks.onParseError?.(raw, err);
                    }
                }
            }
        } catch (err: unknown) {
            if (err instanceof DOMException && err.name === 'AbortError') return;
            callbacks.onParseError?.('', err);
        }
    })();
    return () => { controller.abort(); };
}
```
